Manual tests for the operator

  1. On a small real workflow, turn on Recover on failure on one step (add-step form or step editor) and check that Max recoveries is enabled only while the switch is on.
  2. On the workflow page press List models next to Recovery model, pick a stronger model than the workflow's, and Save.
  3. Force a failure the plan can fix (for example, criteria that contradict the task, with Max retries 0), start it, and watch the Recovering badge in the list and on the page and the "Failure recovery running" banner; try Stop recovery once.
  4. When it ends, read the step's notes tagged Failure recovery (before → after) and check that the relaunch or give-up notification reaches your real channel.
  5. Run npm run target:install yourself and check that ~/.cursor/skills holds create-workflow and target-workflows (version 7) and that ~/.cursor/skills-cursor copies are gone.
  6. Export a template whose step has the toggle on, import it, and check that the fields survive.
